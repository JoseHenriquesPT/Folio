## Handoff — Production save failure: the html_to_text grant (2026-11-04)

- Owner report: one user could not save — notes "stay as unsaved and being able to be recovered", and even new notes would not save. Diagnosed and fixed; **live on hosted now**. If the affected user still sees an existing note fail to save after this, that would be a second, separate problem — get the exact chip/toast text and network status, because every write path was verified working in the repro.
- Root cause: migration 0013 (`0013_security_hardening.sql`) did `revoke all on function public.html_to_text(text) from public, anon` believing `authenticated` kept EXECUTE (the `identity_scoping_test` asserts it, and locally it was true — the platform's `pg_default_acl` had granted it at creation). Hosted has **no default ACLs for functions**, so the revoke left `authenticated` with nothing. The invoker-mode `prepare_note()` trigger calls `html_to_text` at every plain note INSERT/UPDATE, so on hosted: new notes, pin, archive, move-to-notebook, trash, restore and the Joplin import all failed with `403 {"code":"42501","message":"permission denied for function html_to_text"}`. Content saves via the SECURITY DEFINER `save_note` RPC kept working (trigger runs as the definer) — hence drafts piling up and the confusing report.
- Why pgTAP stayed green on 11-03, and the trap for future sessions: **PL/pgSQL caches `prepare_note`'s plan and checks `html_to_text`'s EXECUTE privilege only when the plan is first built in a session.** The test fixtures' owner-side note writes warm that cache, masking the missing grant in every functional test — and on production a pooled PostgREST connection that had run `save_note` first (plan built as definer) accepted later plain inserts while a cold one denied them, which is why this hit "one user" as a mix of symptoms. Only a direct `has_function_privilege` assertion or a **cold** role-switched write catches this class. `supabase/tests/note_write_test.sql` is now that cold guard: own file (own session), first note write is role-switched, and its comment explains why. Keep its first write cold.
- Changed: migration `supabase/migrations/0014_html_to_text_execute.sql` (one explicit `grant execute on function public.html_to_text(text) to authenticated`, `anon` still revoked) and `supabase/tests/note_write_test.sql` (4 assertions: cold insert, derived `body_text`, direct update, update landed). Convention now written down in the migration header: **migrations write grants explicitly (revoke from `public, anon`, grant to `authenticated`) and never rely on a database's default ACLs** — local and hosted do not have the same defaults.
- Red-first evidence: with local temporarily put in hosted's grant state, `note_write_test.sql` failed 3/4 with the exact production error and `identity_scoping_test` #27 failed; after 0014, **pgTAP 217 assertions green**, twice — once on the upgraded local DB and once on a clean `npx supabase db reset` rebuild (all 14 migrations from scratch).
- Hosted (the fix itself): `npx supabase db push --remote --dry-run` showed exactly `0014_html_to_text_execute.sql`, then `--yes` applied it; `migration list --remote` shows 0001–0014 local == remote; `has_function_privilege('authenticated', 'public.html_to_text(text)', 'execute')` is true and `anon` false. Live proof: a **rolled-back** note insert as the owner (`begin; set local role authenticated; insert …; rollback;`) succeeded with `body_text` derived — probe row discarded, verified count 0 afterwards. Nothing else on hosted was touched.
- Browser acceptance (local, fixed stack): new note typed → autosave created it (`POST /rest/v1/notes` 201), chip "Saved", URL resolved to the note id. No frontend change, so **no `npm run deploy`** — the deployed bundle is current.

## What this is

A private notes app for the owner and their partner. The owner keeps a large personal vault; selected notes are shared per note, either read-only or editable. Web app plus installable PWA.

## Product guardrails (do not weaken without agreement)

1. Per-note sharing only (`read` or `edit`), owner controlled. No workspace-wide sharing.
2. Private by default. No public links in v1.
3. The server is the source of truth. No device-to-device sync and no "sync folder" concept.
4. Portability is a feature: every note exports to Markdown/HTML, the vault exports to a zip with attachments and a manifest, plus a full JSON backup.
5. Mobile and desktop are both first-class: responsive from 320px, installable PWA.
6. Simple on the surface. No Notion-style blocks, databases, formulas, or workspace nesting.
7. No live co-editing/CRDT in v1. Version-checked autosave, realtime refresh, and a conflict banner.
8. No offline editing in v1. The app shell and local drafts survive reloads; saves need connectivity.
9. All access is enforced in the database (RLS, storage policies, and security-definer RPCs), not merely hidden in the UI.
10. Attachments are private. Never use a public bucket.

## Decided stack

- Frontend: Vite, React 18, TypeScript (strict), React Router, plain CSS with design tokens.
- Editor: TipTap/ProseMirror, free extensions only, Markdown input rules.
- Backend: Supabase (new, separate project) — Postgres, Auth, Storage, Realtime.
- Auth: Google OAuth plus email magic link, matching ExpenseTracker.
- Hosting: Vercel, manual production deploys.
- Tests: Vitest for TypeScript; pgTAP SQL tests for access rules (`npx supabase test db`).
- Import/export: Turndown, JSZip, marked, DOMPurify.

## Repository conventions

- `src/db/` — typed Supabase access. No UI imports here.
- `src/lib/` — pure logic, with a colocated test (`x.ts` / `x.test.ts`).
- `src/hooks/` — React hooks that combine the data layer with component state.
- `src/components/`, `src/pages/` — UI, one component per file.
- `src/styles/` — design tokens, app shell, workspace, and editor styles.
- `scripts/` — local-only utilities such as the seeded-vault generator.
- `supabase/migrations/NNNN_name.sql` — ordered, forward-only migrations.
- `supabase/tests/*.sql` — pgTAP access-control tests.
- Keep files small and focused. No commented-out code. No `any` without a written reason.
- The note body is stored as sanitized HTML (`body_html`); the database derives plain text and the search vector.
- Auth uses PKCE. Do not switch it to implicit flow.
- Local magic-link emails are read in Mailpit at `http://127.0.0.1:54324`.
- UI language is English unless the owner asks for i18n.

## Security and deployment

- RLS enabled on every table containing user data. Test owner, editor, reader, and stranger for every path.
- No service-role key in the browser. Only the publishable/anon key; RLS does the work.
- Content saves go through a version-checked `save_note` RPC. Editors cannot touch notebooks, share rows, pin/archive/delete state, tags, or attachment records.
- Sanitize imported or generated HTML before rendering.
- Deploy the database before the frontend. Validate migrations locally, then apply to hosted with `scripts/apply-migrations.ps1`; the full sequence is in `docs/DEPLOY.md`.
- Keep the Vercel Git integration disconnected. Deploy with `npm run deploy` (`vercel --prod`).
- After deploying, verify the production bundle contains a new marker string.
- Never publish the live URL, Supabase project ref, keys, or team slug in public docs.
